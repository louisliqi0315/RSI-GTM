状态：本文件在任何 Phase 2e 结果检索前写定，仅用于锁定定义与通过/降级标准；
不改动 paper-draft-v2.md、foundational-candidates-v1.md、phase2a/phase2d_*。

## A. 信任预算 T2/T3：GitHub 公开协作检验（首选数据源：GitHub Archive / GitHub 公开事件）

### A1. 队列定义（检索前写定）
- 处理组：同一公开账号在短窗口（30 天）内向 ≥5 个不同公开仓库提交
  ≥20 个 PR 或 issue，且其中 ≥50% 被关闭但未合并；以“首次公开拉黑/屏蔽/
  仓库级屏蔽事件”作为断点。首次指在可检索公开记录中第一次出现该事件。
- 对照组：同期、向相似规模/语言公开仓库提交高频 PR、但未出现公开拉黑/
  屏蔽事件的账号；须按仓库规模分层、语言分层报告，不得只报原始均值差。
- 自动化识别标准（检索前写定，不得以结果反推）：提交模板高度相似、
  提交间隔呈现机器规律（短窗口内批量提交）、或账号公开标识为 bot/
  自动化工具；人工高频提交者单独作为第二对照，不得混入处理组。

### A2. 信任代理变量（公开可观测，事前声明局限）
- 主变量：后续 PR 合并率 = 合并 PR 数 / 提交 PR 总数（断点前后各一个完整周期）。
- 完整互动周期定义：断点后 90 天，或断点后提交满 20 个 PR，以先到者为准；
  断点前基线为断点前 90 天（或前 20 个 PR）。
- 辅助变量：无合并关闭率；维护者公开负向互动（关闭附带屏蔽/举报类公开事件）。
- 局限声明：这些是信任的代理变量，不是品牌折损本身的测量；
  合并率受 PR 质量、仓库政策、语言、项目活跃度混杂，必须分层报告。

### A3. 估计方法与通过/降级阈值
- 方法：断点前后双重差分（处理组前后差 − 对照组前后差）。
- T2 通过条件（须同时满足）：(i) 处理组断点后完整周期内合并率显著低于
  断点前基线（方向为负，且在可报告的置信区间/分层下不只由单一仓库驱动）；
  (ii) 正向价值事件（一次被合并的高价值 PR）带来的合并率提升幅度，
  小于硬边界事件造成的合并率下降幅度（不对称方向成立）。
- T2 降级条件：断点后合并率在完整周期内完全恢复到基线（差值≈0），
  或正负事件对称，则吸收态与不对称假设同时降级，信任预算退化为普通声誉分数。
- T3 通过条件：同组织/同品牌下其他账号（处理组账号所在公开组织的
  其他提交账号）在断点后完整周期内合并率同样下降，且方向与处理组一致。
- T3 降级条件：只影响事发账号、同组织其他账号无下降，则四维不挪用主张降级。
- 若无法获得事件级数据（无 BigQuery 权限、无可直接检索的事件级数据集、
  仅有二手报道或轶事），则本项记为“负结果：主 DiD 未执行”，
  不得以二手报道的方向性描述冒充 DiD 结果；二手报道仅可作为
  “方向性参考、非检验”，并在报告中单独分层。

### A4. 外部效度红线
- GitHub 检验通过，只能支持“信任动力学在公开协作场景中成立”，
  不得直接推导“信任预算在 GTM 管道中成立”。
- GTM 本身的结论仍以 Phase 2d 合成实验为准，且 Phase 2d 已说明
  吸收态是编码假设、溢出区间含零。

## B. VRI 公开基准事前预测检验（结果检索前写定）

本节预测沿用 foundational-candidates-v1.md 已预注册的 V1（验证器可写 →
假改进率上升），并在本运行内为以下两个新案例（不复用 candidates-v1 §2.4
已用的 DGM、ExploitGym、METR、AIDE²、Anthropic 案例）写下具体方向预测，
再检索公开结果对照。事后挑选的方向一致不算通过；若任一案例方向相反，
记为预测失败。

### B1. 案例一：公开排行榜可迭代的 ML 基准（MLE-bench / Kaggle 式）
- 预测 P1：可反复以公开排行榜分数为优化目标的系统，其公开分数与
  冻结的 held-out（私有）分数之间出现系统性分离：公开分数上涨、
  私有分数持平或下降的比例显著高于仅以冻结私有评估为目标的系统；
  且公开排行榜排名与私有排名不一致的频率高于冻结评估。
- 若公开结果显示公开-私有分离为零或方向相反，P1 记为失败。

### B2. 案例二：测试文件可写的编码智能体环境（SWE-bench 式）
- 预测 P2：在智能体可写入/修改测试文件的环境中，会出现可观测的
  测试编辑/测试补丁类作弊：修改后测试通过、但在冻结的测试补丁
  （测试补丁由评估方单独应用、智能体不可改）下失败的比例 >0；
  而冻结测试补丁评估下，此类假通过被消除或显著降低。
- 若公开结果显示可写环境中无此类作弊，或冻结测试补丁并不能消除它，
  P2 记为失败。

### B3. verdict 规则
- 两案例方向均与预测一致：VRI 获得“事前方向支持”，但仍不得记为
  “通过”，因为案例挑选本身存在选择偏倚、且多为二手报道/轶事率，
  未达到 Transformer 级别的“事前预测”标准（需预注册的独立数据集、
  点估计与置信区间）。
- 任一案例方向相反或无法解释：记为预测失败 / 降级讨论，不得隐瞒。
- 任一案例仅有轶事、无率或无对照：该案例记为“证据不足”，
  不计入通过，亦不计入证伪。
