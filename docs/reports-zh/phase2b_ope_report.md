# Phase 2b OPE 单元测试报告（核心交付）

> 合成数据声明：以下全部为合成数据，不是真实厂商数据，不宣称任何真实转化率提升。
> 运行：`python3 phase2b_ope_run.py --out phase2b_ope_results.json`
> 代码：`phase2b_ope.py`、`phase2b_ope_run.py`（仅 Python 标准库）

## 0. 先说结论：OPE 能测什么、不能测什么

- **孤立 bandit 设定下，DR / SNIPS / IPS 能大致恢复排序，但不是稳健地恢复。**
  在 n=2000、探索率 0.3、无混杂时，DR 排序与真值排序的 Spearman 为 0.6，
  顶名被 G 变体抢走（真值顶名是回复率贪心）；探索率升到 0.7 时 DR 才恢复
  顶名（Spearman 0.943）。换句话说：**OPE 的结论对 logging policy 的探索量
  极其敏感**，而真实 GTM 日志的探索量通常远低于 0.7。
- **隐藏混杂本身不翻转排序，propensity 错设才翻转。** 这是最重要的区分：
  warm 账户（奖励放大、logging 更倾向深度触达）且估计器使用真实 propensity 时，
  DR 排序 Spearman 仍为 0.943；一旦估计器误用“忽略 warm”的观测-only propensity，
  Spearman 跌到 0.371，回复率贪心从第 1 跌到第 5。更强混杂（warm 50%、奖励 3 倍、
  改写 90%）在真实 propensity 下也未翻转顶名（Spearman 0.771，差异主要来自
  G 阈值变体的并列）。结论：**真实世界 OPE 的生死线不是“有没有隐藏变量”，
  而是“logging policy 是否可被观测变量完整刻画”。** GTM 日志里，销售的人工
  直觉、关系、线下信息恰恰是无法被观测变量完整刻画的，因此 OPE 结论必须配
  敏感性分析（Rosenbaum 界），不能只报点估计。
- **序贯 naive DR（把每周当独立 bandit 样本）系统性高估，且不能测 G+ 的门。**
  用 1000 账户大样本真值作对照（见 §3），naive DR 的周均奖励比真值周均高
  约 1.7–2.1 倍，排序 Spearman（排除无效的人工规则后）为 0.7，
  G+ 有门与 G 在日志种子下完全相同（门一次未通过，参数未变），而真值种子下
  两者不同——**跨种子比较本身就是噪声**。因此：naive bandit OPE 不能作为
  G+ 的验证层，论文必须写明它只是一个“方法论单元测试的反例”，
  真正的序贯评估需要序贯 OPE / 仿真 + 影子模式 + 聚类 RCT 三层（Phase 2 §5.2）。
- **G 阈值变体在一步设定下不可区分，这不是 OPE 的错，是仿真机制的识别问题。**
  lambda=3 的信任影子定价在 obs < 0.5 时把 LIGHT / TRIAL / DEEP 全部压成 WAIT，
  因此 G_0.35 / G_0.40 / G_0.45 在一步实验里 DR 完全相同（0.25）。
  阈值差异只在多周、意图爬高后才显现。论文中不得用一步实验宣称“阈值不重要”。

## 1. 实验设计（可复现）

### OPE-1 孤立 bandit
- 上下文：仿真器账户经 12 周 WAIT 热身演化后的状态（意图、track、segment、
  声誉、触达历史）。**热身是必需的**：新账户意图上限为 0.45，恰好卡在
  合格门槛下，一步奖励恒为 0——第一版实验全零就是因此发现的，已修正，
  不是把零当结果。
- Logging policy：以 0.7 概率跟随 G（阈值 0.40、lambda 3），以 eps 概率均匀探索；
  eps 默认 0.3，扫描 0.05 / 0.3 / 0.7。
- 目标策略：回复率贪心、人工规则、WAIT-heavy（解析 pi）、G_0.35 / G_0.40 / G_0.45。
  **注意**：一步设定下有门/无门尚未递归，退化为 G，故用 G 阈值变体代替，
  不假装测了递归。
- 奖励：一步管道增量（合成单位）；信任消耗单独记录，OPE 估计的是期望管道，
  不是 Pipeline-per-Trust 比率（比率需用管道期望 / 信任期望另算）。
- 估计器：IPS / SNIPS / DM / DR，Q 用分组均值，**2 折交叉拟合**（按账户分折），
  避免 Q 在同一批数据上拟合又评估的 in-sample 过拟合（第一版未交叉拟合时
  小样本 DR 出现 0.75 等失真值，已修正）。

### OPE-2 序贯 naive
- 日志：200 账户 × 24 周，logging policy 为 eps-greedy G（eps 0.3），种子 501。
- 上下文必须取**动作前**的值（声誉、触达历史、是否已合格、伙伴效能）。
  第一版误取动作后值，导致结果泄漏进上下文、DR 系统性高估更严重，已修正。
- 真值：1000 账户 fresh run（种子 999），每账户总管道 / 1000。
  **注意**：真值种子与日志种子不同，G+ 有门的参数演化因种子而异，
  因此有门 vs G 的比较在 OPE-2 中是跨种子比较，噪声大，不得据此下结论。
- 人工规则在序贯设定下**无效**：其内部计数器是目标策略自身的反事实历史，
  无法从 logging 轨迹恢复，故排名计算排除它，仅作示意保留。
  这本身就是一个发现：naive bandit OPE 不能评估有状态规则策略。

## 2. OPE-1 结果（n=2000、eps=0.3、无混杂，除非另注）

真值（20000 样本蒙特卡洛，一步期望管道）：
回复率贪心 0.342 > G_0.35 0.253 > G 0.228 > G_0.45 0.214 > 人工规则 0.208 > WAIT-heavy 0.019。

DR 估计：G / G_0.35 / G_0.45 并列 0.250，回复率贪心 0.197，人工规则 0.069，
WAIT-heavy 0.007；DR 排序 Spearman 0.6，顶名错误。
IPS 排序与 DR 相同方向；SNIPS 排序为 G_0.35 > G > G_0.45 > 贪心 > 人工 > 等待，
同样未恢复顶名。**在默认探索率下，OPE 低估了回复率贪心的一步价值**，
因为贪心在低意图上下文也触达，而 logging 数据在低意图区触达样本稀少，
Q 外推不足。

### 样本量扫描（DR）
- n=100：DR 排序 Spearman 0.943，但数值失真（人工规则 0.0、贪心 0.867）——
  排序“对” largely 是并列与小样本噪声的巧合，不得引用。
- n=500：人工规则仍为 0.0（稀疏奖励 + 分组 Q 在小样本下无合格样本）。
- n=2000 / 10000：人工规则恢复到 0.117 / 0.203（真值 0.208），
  说明**稀疏奖励策略的 OPE 至少需要数千样本**，数百样本的 OPE 表格不可信。
- G 阈值变体在所有样本量下并列（见 §0 的 lambda 掩盖解释）。

### 探索率扫描（n=2000）
- eps=0.05：DR Spearman 0.6，IPS Spearman 0.6——近确定性 logging 下，
  未探索动作的 Q 几乎无数据，OPE 无法恢复排序。
- eps=0.3：同上 0.6。
- eps=0.7：DR Spearman 0.943，顶名恢复；IPS 仍为 0.6（IPS 方差大）。
  **结论：DR 需要高探索率才能恢复排序，而真实 GTM 日志的探索率通常很低。
  因此“DR 在合成设定下成立”不能外推为“DR 在真实日志下成立”。**

### 隐藏混杂（n=2000、eps=0.3）
- 真实 propensity + 不含 warm 的 Q：DR Spearman 0.943（仅人工与 G 顺序互换）。
- 真实 propensity + oracle Q（含 warm）：DR Spearman 同为 0.943——
  oracle 并未改善，因为 DR 的双重稳健性已由正确 propensity 保证。
- **观测-only propensity（忽略 warm 改写）**：DR Spearman 跌到 0.371，
  回复率贪心从第 1 跌到第 5，人为规则升到第 1。**这是 OPE 翻转的真正条件。**
- 更强混杂（warm 50%、奖励 3 倍、改写 90%）+ 真实 propensity：
  DR Spearman 0.771，顶名未翻转，差异主要来自 G 阈值并列。

## 3. OPE-2 结果（序贯 naive，200 账户日志 vs 1000 账户真值）

真值（每账户总管道）：回复率贪心 3.143 > 无门 2.856 > G 2.774 > 有门 2.566 >
人工规则 2.081 > WAIT-heavy 0.224。
**注意**：此真值种子（999）下有门低于 G，与种子 42 的单种子表方向相反——
这本身就是多种子不稳定性的又一证据，不得挑种子。

Naive DR（周均奖励，排除人工规则）：回复率贪心 0.273 > G 0.201 = 有门 0.201 >
无门 0.196 > WAIT-heavy 0.013；排序 Spearman 0.7。
真值周均（总管道 / 24）：贪心 0.131、无门 0.119、G 0.116、有门 0.107、等待 0.009。
**DR 系统性高估约 1.7–2.1 倍**，机制是吸收态 carryover：
账户一旦合格，后续周奖励恒为 0，但 naive DR 用 logging 轨迹的上下文
（账户在 logging 下尚未合格的周）去评估目标策略，相当于假设目标策略
永远不会提前合格，从而重复计算本应只发生一次的管道。
有门 DR 与 G 完全相同，是因为日志种子下有门参数一次未变（门未通过），
而真值种子下有门参数已变——**跨种子比较使有门结论无法从 OPE-2 得出**。

## 4. 对论文的收缩点（直接可用）

1. OPE 章节的标题主张应收缩为：“在已知 logging policy、充分探索、
   无 propensity 错设的合成设定下，DR 能恢复大致排序；一旦 propensity
   错设或探索不足，排序即翻转。” 不得写“DR 已验证 G+ 有效”。
2. 序贯评估不得只用 bandit OPE：必须同时报告仿真、OPE（带敏感性分析）、
   影子模式、聚类 RCT 四层，且 OPE 层要注明“吸收态 carryover 使 naive
   估计高估约 2 倍（本合成设定）”。
3. 任何 OPE 表格必须同时报告：logging policy 的探索率、样本量、
   propensity 是否为已知/估计、敏感性分析结果、以及 Q 的交叉拟合方式。
   缺其中任何一项的 OPE 表格，在本论文标准下视为无效。
4. 人工规则类有状态策略不在 bandit OPE 的适用范围，须用仿真或序贯 OPE
   另行评估，不得混进同一张 bandit OPE 排名表。

## 5. 本实验未做的事

- 未实现完整序贯 OPE（如 Fitted Q / 重要性加权轨迹法）；未做 Rosenbaum 界
  的数值敏感性分析（只做了 propensity 错设的定性翻转演示）。
- 未用真实日志（无真实日志可用）；未对信任比率做 OPE（只做了管道期望）。
- 未承诺任何厂商合作时间表；未对外联络任何人。
