# GTM-Sim v0 + 公开信号面板（Phase 2a 原型骨架）

> **合成数据声明**：本目录下所有运行结果均为合成数据，不是真实厂商数据，
> 不是任何厂商的转化率、收入或表现。绝不以此宣称任何真实转化率提升。

## 文件清单

| 文件 | 作用 |
|---|---|
| `gtm_sim.py` | 仿真器核心：合成账户、信任动力学、六个基线、G+ 递归与验证门（仅标准库） |
| `run_experiment.py` | 运行入口：六基线对照，输出 JSON + 终端表格 |
| `example_output.json` | seed=42 的完整运行结果（与 `example_output.md` 同一批） |
| `example_output.md` | seed=42 结果表 + 解读 + 换种子抽查说明 |
| `public_signal_panel.md` | 公开信号面板 schema（周频、segment/cohort 级）+ T1–T3 评估骨架 + F1–F5 |
| `public_signal_panel.schema.json` | 面板行的机器可读 JSON Schema |

## 如何运行

```bash
cd ~/workspace/gtm-research/phase2a
python3 run_experiment.py --seed 42 --accounts 200 --weeks 24
# 换种子 / 规模：
python3 run_experiment.py --seed 7 --accounts 200 --weeks 24 --out /tmp/out_seed7.json
```

- 依赖：**仅 Python 标准库，Python 3.10+**，不需要 pip install。
- 运行时间：200 账户 × 24 周 × 6 基线（含递归验证集）在普通机器上 < 1 秒量级。
- 输出：终端表格（主指标 + 强制伤害指标并列）+ JSON 文件。
  **只报主指标、不报伤害指标的运行结果视为无效** —— 本脚本不提供这种输出模式。

## 输出示例（seed=42，合成数据）

见 `example_output.md`。一句话摘要：有门递归主指标最高、伤害最低，

## 设计对照（对应 phase2-report.md §5）

- **动作空间**：Track 1（WAIT、轻触达、深度触达、试用激励、转人工）+
  Track 2（伙伴协同触达、伙伴使能、停止冷静）+ 两轨共用的 WAIT。
- **六个基线**：回复率贪心、人工规则、WAIT-heavy、G（无递归）、
  G+ 有门递归、G+ 无门递归（消融）。
- **验证门（最小实现）**：G1（验证集 Pipeline-per-Trust 提升）+
  G3（伤害不恶化 + 防“永远等待”）+ G5（信任预算不超支 10% 以上）；
  G2 由独立验证种子近似，G4 由代码结构保证（评估函数在任何候选下都不变，
  候选只能改阈值与 λ，不能改指标定义）。
- **强制披露**：退订率、投诉率、声誉变化、WAIT 占比、否决/回滚次数，
  与主指标 Pipeline-per-Trust 同表输出。

## 已知局限（仿真 ≠ 真实，务必先读再引用）

1. **仿真机制是假设，不是测量**：意图演化、组织事件概率、声誉衰减系数、
   伙伴分成系数 0.7、信任预算 30 全部是 v0 的设定值，未经任何真实数据校准。
   换一组设定，结果方向可能变化 —— 本原型证明的是“代码能跑、对照能分出差异”，
   不是“G+ 在真实世界有效”。
2. **主指标可被博弈**：Pipeline-per-Trust 的分母很小时（触达极少），比率会虚高；
   WAIT-heavy 在不同种子间主指标波动极大就是证据。下一版必须加最小产量门槛，
   或改用“主指标 + 绝对管道量”的帕累托比较，不得单独以比率排名。
3. **OPE 层尚未独立成模块**：本原型用“独立验证种子”近似离线评估，
   但 phase2 §5.2 要求的“用已知 logging policy 生成日志、再用 DR/SNIPS 反推排序”
   的方法论单元测试尚未实现，是最值得补的第一缺口（见下）。
4. **公开信号 ≠ 转化率**：面板只有 schema 与 T1–T3 骨架，没有采集真实数据；
   即使未来采集，也只能预测代理标签（热度 / 爬坡 / 衰减），不能宣称转化率。
5. **未验证假设清单（接 phase2 §6）**：U1 信任预算是否为厂商真问题、
   U2 公开信号对爬坡率是否有预测价值、U3 信任消耗是否可预测、U4 验证门是否有净价值
   （本原型仅在合成设定下方向性支持，未在真实数据上验证）、U5 跨场景泛化、
   U6 伙伴净留存是否可建模、U7 厂商 GTM 预算归属（永远写“未公开”）、
   U8 信号→成交的中国市场因果量级（永远写“待验证”）。
6. **红线**：不访谈、不对外联络、不爬取、不购买、不推断个人数据；
   不以“绕过买方过滤器”为优化目标；不把媒体口径当财报、不把 token 量当收入。

## 下一步最值得补的缺口（按优先级）

1. **OPE 方法论单元测试**：仿真器生成带已知 logging policy 的日志，
   用 DR / SNIPS 反推策略排序，检验在已知真值下 OPE 能否恢复排序。
   没有这一步，未来拿到真实日志也无法信任评估结果。
2. **主指标加产量门槛**：Pipeline-per-Trust 仅在绝对管道 / 合格数达到门槛时
   才参与排名，堵住“几乎不做刷比率”的漏洞；同时报告帕累托前沿。
3. **多种子 + 参数敏感性报告**：固定 10 个种子跑六基线，报告均值与置信区间，
   而不是单种子表格；并对声誉衰减系数、信任预算做敏感性扫描。
4. **公开面板的真实采集（仅公开来源）**：按 schema 采集一小批公开周频行，
   先跑 T1 持续性基线，检验“时序模型是否打得过基线”—— 若打不过，
   就是有价值的负结果，应如实写进论文。
